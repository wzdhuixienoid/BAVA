# 模拟理财

v0.11.1 提供 `/wealth` 理财中心及工作台理财结果、核对卡。全部产品为虚构人民币开放式净值型理财，无本金或收益保证，不另收持续管理费。净值和近30日变化、最大回撤均为模拟历史。

## 使用

1. 开启 `MOCK_WEALTH_ENABLED=true`，执行 Alembic `upgrade head`，重启 API。启用后的启动过程幂等导入共享产品、净值、说明书、风险揭示和 FAQ；不会生成持仓或扣款。Settings 默认关闭，Docker development 示例开启，production 拒绝开启。
2. 打开理财中心，浏览产品与资料，选择至多4个产品对比。未测评仍可查询。
3. 本人逐题完成8题风险测评。答案0至4分，版本 `mock-v1`，有效12个日历月。这是 Mock 规则，不是法定标准。重要信息改变时重新测评；新测评保留旧记录，订单证据不覆盖。
4. 输入需求、可选金额和本人账户获得至多3个产品的确定性推荐。要求保本、不接受损失、即时用钱者不获得申购推荐。
5. 点击申购，补全产品、有效人民币储蓄/借记账户、总金额。核对估算费用、份额、具体交易日和预计成交时间，明确确认，开始并通过 Mock 强验证，再提交。
6. 已受理时冻结资金，等待成交。申购最终结算后扣款、退款及份额同事务入账。核对卡估算不构成实际成交事实。
7. 在持仓选择部分或全部赎回，账户限定本人该产品持仓的原付款账户。赎回也须确认及强验证。受理冻结份额，成交扣减份额，下一模拟交易日到账前，待到账资金单列且不计入可用余额。
8. 查看订单中文状态、实际净值、费用、份额、价款/到账及余款退款；打开原资料、对话过程与审计。成交、到账消息可已读或删除，恢复不重复生成。

自然语言示例：

```text
有哪些模拟理财产品？
比较演示稳享日日和演示稳健优选。
根据我的测评推荐稳健理财，打算投资1000元。
演示稳健优选的申购费用和到账规则是什么？
从工资卡申购演示稳健优选1000元。
赎回工资卡的演示稳健优选10份。
查询我的理财持仓和订单。
```

资料问答通过关键词和别名检索当前有效版本；历史订单检索绑定原资料版本。缺少证据明确说明没有找到。页面“查看资料”通过已认证客户端打开内容，不暴露不可访问的编号。模型不能修改费用、风险、排序或代填测评。

## 规则

产品风险是独立 R1–R5 类型；测评客户等级为 C1–C5。分段为0–6、7–12、13–19、20–25、26–32。损失承受选择1/2/3时最高C1/C2/C3，选择0或投资目标“必须保本”时所有产品不适合。测评过期或客户等级下降不阻止已有持仓赎回。

推荐按风险偏好距离、较低风险、下一开放日、申赎总费率、产品ID排序；保守/稳健/均衡/进取对应R1/R2/R3/R4。一周内可能用钱排除周开放产品；即时用钱排除全部异步产品。金额按总申购金额检查起购，有账户时再检查共享可用余额。

模拟交易日为北京时间周一至周五，无真实节假日。严格早于15:00归当日开放日；15:00及以后归下一开放日。交易日18:00发布净值，下一交易日10:00确认，赎回再下一交易日10:00到账。跨截止点、测评或产品版本变化必须重新核对、确认和强验证；确认600秒、强验证300秒，不延长。

订单：已受理待成交 → 已成交待到账（赎回） → 最终完成。申购成交与最终完成同事务。未知结果保留最后订单阶段和占用，恢复查询原Operation；不会另建扣款。普通GET不推进结算。受理后不可撤单，未提交草稿可取消。已受理后触发安全锁，仍继续结算及到账。

金额两位小数，净值/份额六位；费用与现金四舍五入，申购份额向下舍入。余款为总金额减费用减份额价款。边界无法产生正份额或非负退款时明确拒绝。缺少已发布净值不能交易或估值，不默认净值1。理财本金和费用独立账本，不混入消费统计。

## 范围

支持单独查询、推荐、对比、资料问答、持仓、申购、赎回。条件自动投资、多笔写业务、定投、调仓、封闭式产品、基金、真实银行、部分成交及受理后撤单均不支持。含条件的请求整体拒绝，不丢弃条件执行交易。自然语言不能唯一确定产品、账户或数量时在核对卡补全。

净值fixture范围2025-01-01至2027-12-31；未来记录不可被提前读取。超出范围的已受理订单缺少成交日净值时保留待成交和占用，恢复查询并显示净值缺失，不能伪造成交。生产禁用Mock，真实金融渠道与真实MFA不在本次范围。

## 暂停新业务

设置`MOCK_WEALTH_ENABLED=false`并重启开发/测试API后，页面显示“已暂停新理财交易，已受理订单继续处理”。订单、持仓、资料和处理进度仍可查看，未提交草稿可取消。新申购、赎回、测评和授权暂停；已创建但未受理Operation明确拒绝，不冻结资金。已受理订单继续成交和到账，UNKNOWN查询原操作且保留占用，不应重新下单。production始终禁止Mock执行。

## 数量与全部赎回

申购数量必须是金额（元），赎回必须是份额（份）；“赎回100元”不会被改成100份，“申购1000份”不会被改成1000元。缺少单位、多数量或矛盾单位时先补充。支持常见空格、人民币符号和规范千分位；精度和上限由后端严格校验。

持仓卡“全部赎回”使用后端提供的份额字符串，生成具体数量核对；自然语言可说“全部赎回工资卡的演示稳健优选”。产品和原付款账户无法唯一确定时先选择。无持仓或份额为零时明确拒绝。核对之后份额被其他订单占用会拒绝提交，需重新核对，不能静默减量。仍须确认和强验证。

## 本次推荐需求

有效C5测评也不覆盖本次明确要求。“必须保本，不能亏本金”和“我想进取，但不能接受任何本金损失”均无适配产品。“只要稳健，不要进取”排除进取等级，并只选稳健及更低风险；“不要高风险，偏保守”优先保守且排除高风险。“不要求保本，可以承担波动”不会误判为要求保本，“不需要马上用钱”不会误判为即时用钱。无法可靠理解或相互矛盾的需求先补充，不能忽略后返回默认推荐。无适配产品返回空列表及原因，不放宽约束凑数。

## 状态与刷新

失败订单展示具体中文原因和下一步，过程和审计入口保留。明确失败且无占用、UNKNOWN占用保留、赎回成交后待到账分别显示。缺少成交日净值时等待原订单查询，不伪造成交。预计下次处理时间未知时不显示时间；实际到账仅以最终账本为准。

资料与问卷首次或版本变更时加载，可主动刷新；持仓、订单、余额、测评及理财Workflow统一轮询。页面隐藏暂停，恢复可见立即刷新，请求不重叠；失败保留旧数据并提示重试。交易卡修改期间轮询不覆盖未保存输入，需先保存才能确认/提交；版本冲突刷新并提示重新核对，不自动重试提交。页面创建草稿与对话/消息/任务同事务，并用创建键幂等，创建失败不留下空对话。

## 工作台展示

理财查询用产品卡、资料摘录、持仓与订单展示保存的业务结果。推荐只展示最终筛选的产品，不重复列出中间查询的完整目录；保存的历史对话也使用同一展示方式，不改写历史消息或交易事实。风险、起购金额、费用、净值日期和估算说明保留；工具调用原文、内部产品编号、接口路径和排序实现不在默认回复中展示。资料按钮以产品说明书、风险提示和交易说明命名，点击后通过已认证客户端打开相应原版本资料。
