# 多步骤任务与条件

工作台可以把已注册的查询和工作流组成有限计划。普通“查余额并分析消费”由 PersonalBankingAgent 一次处理；跨订阅、工作流或带条件的组合才需要 Plan。

## 支持的请求

```text
先分析订阅，再取消星幕视频。
查工资卡余额，如果余额不少于3000元，给张三转500元。
分析本月消费，如果消费不少于5000元，取消星幕视频。
```

当前计划能力是账户查询、消费分析、订阅分析，以及转账、订阅取消／恢复工作流。最多 8 步、2 个条件和一个写工作流。单独生成报告有专门路径，复杂计划不包含报告生成、理财交易或 AA 能力。

条件仅支持账户余额、月消费或订阅月成本“不少于”明确阈值。金额必须来自对应条件原文，“余额够”“花太多”会要求明确标准，不能把转账金额当作余额阈值。

## 处理过程与等待

处理过程展示步骤、依赖、查询结果及条件证据。条件使用可信源的金额、币种和输出 hash 确定性计算；FALSE 跳过受保护步骤，TRUE 才进入工作流，仍需要确认和所需强验证。

| 状态 | 含义 |
| --- | --- |
| 运行中 | 执行已满足依赖的步骤 |
| 等待用户 | 需要选择、核对、确认或验证 |
| 等待外部 | 原业务操作尚未确定结果 |
| 已暂停 | 自动编排已交由用户处理 |
| 步骤跳过 | 条件未满足，不创建对应写业务 |
| 完成／失败 | 编排已结束，资金结果仍须核对关联工作流和 Operation |

计划及步骤保存在数据库中，Task lease 和 checkpoint 支持恢复；刷新页面不新建计划或重新授权。

## 手动处理与回退

活动计划可“转为手动处理”，暂停自动编排并继续在业务卡上处理；“继续自动执行”恢复原计划。暂停不会撤销已提交操作，也不会停止原 Operation 的结果恢复。

只有目标及全部受影响后继均为只读／条件步骤、且未关联工作流时，才提供“回退并重新执行”。回退清除这些步骤的查询结果，按原依赖重新执行；不能撤销转账或跨越写业务回退。

## 限制

不支持 ELSE、嵌套条件、AND／OR、循环、任意表达式、多笔写业务或动态重规划。复杂请求不能通过丢掉条件或后半段来执行部分资金动作。计划不会替用户确认，模型也不能扩展能力清单。

确定性规则见 [金融计算与计划](../architecture/algorithms.md)，身份和授权见 [安全边界](../architecture/security.md)。实现入口：[能力登记](../../apps/api/src/banking_api/planning/registry.py)、[计划校验](../../apps/api/src/banking_api/planning/validator.py)、[用户动作](../../apps/api/src/banking_api/application/plan_service.py)。
