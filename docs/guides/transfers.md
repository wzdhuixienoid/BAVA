# 转账与收款

全部流程使用模拟银行。当前仅支持人民币银行卡收款人，不支持手机号转账或换汇。

工作台左侧统一从“转账与收款”进入，在 `/transfers` 选择“预约与周期转账”“AA 收款与付款”或“收款人管理”。各管理页面可返回此入口；从转账草稿进入收款人管理时，仍可返回原对话继续办理。即时转账和发起 AA 仍在工作台对话中进行，处理过程、结果与审计链都在对话中查看。

## 转账历史

“我最近有哪些转账”“查看今年转出记录”“查询上月转入记录”通过 PersonalBankingAgent 只读查询已入账账单，可按账户、时间和对手方/备注筛选，并连续翻页。它与金融总览使用同一账单来源，不会创建新的转账草稿，也不调用会推进状态的对账工具。未完成、失败及未来预约不计入已入账历史；这些状态在原办理记录或预约页面核对。

回复先展示分析区间、转出/转入总额和笔数，再按收款人/付款方列出金额、笔数及占比，说明资金集中在哪些对手方、最近一笔发生于何时，并展示最近明细。也可输入“分析最近30天的转账，按收款人统计总额”。汇总基于全部匹配记录，翻页不会把总额缩成当前页金额；同名收款人按银行和尾号区分，不同币种分别展示。

## 即时转账

输入“从工资卡给李小雨转 1 元，备注餐费”。选择账户及收款人，核对金额、账号和备注，再确认、完成 Mock 强验证并提交。所有金额都需要强验证。

同名或简称匹配结果必须由用户选择。没有匹配时补充资料，或到 `/payees` 核对姓名、虚构银行、完整模拟账号与可选别名后确认保存，再返回转账草稿。模型不能替用户确认收款账户。

备注最多 100 个 Unicode 字符，不接受控制字符；非空备注纳入确认 hash。修改付款账户、收款人、金额或备注会使原确认和强验证失效，需要重新核对。

## 单次预约

配置 `MOCK_SCHEDULED_TRANSFERS_ENABLED=true` 后，可输入“明天早上 9 点从工资卡给物业转 200 元”。时间语义由模型提取，后端按请求接收时间与北京时间计算、校验并展示。不明确的日期或时刻需要补充。

流程为核对 → 确认 → 强验证 → **授权并创建预约**。创建后等待到时自动执行，无需用户再次提交。默认最少提前 60 秒、最长 30 天、迟到执行窗口 300 秒；运行参数见 [环境配置](../development/setup.md)。

预约不冻结余额。到时重新检查账户、余额、收款目标、安全锁和授权范围；未提交且超出窗口的预约过期，不无限补扣。已提交而 UNKNOWN 的操作继续恢复查询。

## 按月周期

输入“每月 1 号上午 9 点给物业转 100 元，共 3 次”。必须明确时刻和有限总次数；核对卡逐项展示实际日期、每期金额及授权总额。

当前仅按月，2 至 12 次、跨度最多 366 天。29／30／31 日遇到没有对应日期的月份会跳过，实际期次以核对卡为准。强验证后显式授权创建，每期拥有独立预约、一次性授权与唯一 Operation。

授权后不能直接改金额或日期；需要撤销未提交授权，再创建并重新确认。某一期失败不代表其余期次成功，也不自动补扣。

## 管理预约与对话

在 `/scheduled-transfers` 查看每期结果。未提交的期次可取消，周期可撤销后续授权；已提交或 UNKNOWN 的操作继续查询，不能通过普通取消抹掉提交事实。

已取消的预约可从列表软删除；周期须全部期次取消且没有 Operation 才可整组移除。业务授权、账本与审计保留。

删除对话不会撤销已授权预约。未完成授权的任务或正在提交、未收敛的资金操作会阻止删除对话。

## AA 收款

输入“昨天聚餐 100 元，和张三、李四 AA，我也参与”。参与者栏只填其他人，“我也参与”通过独立选项设置；核对时有问题的字段显示红框及具体原因。

金额按整数分分摊，余分确定性分配；也可手动填写每人金额，要求人数、精度和总额一致。发起者自己承担的份额不经系统扣款。确认发布仅建立收款请求，其他参与者须用自己的身份选择付款账户并完成转账确认、强验证与提交。

`/aa` 查看收款与付款。撤回取消尚未付款的请求，不重新分摊已确认金额，保留已付款证据；提交中或 UNKNOWN 不能直接撤回。

全部其他参与者的份额都已取消，且没有付款提交记录时，发起者可点击“删除收款”并确认，从自己的列表移除该请求。删除保留原请求、份额与审计；原对话显示删除说明，其他参与者仍可查看自己的历史。待付款、部分取消、已付款、结果未知、拒绝或过期的请求不能按此入口删除。AA 页面不再展示开发身份切换控件；隔离多身份测试仍可使用受开发配置约束的 Mock 会话 API。

多身份演示仅在显式开发配置下启用：`MOCK_PARTICIPANT_LOGIN_ENABLED=true`，并配置至少 32 字符的私有 `MOCK_PARTICIPANT_SIGNING_KEY`。它不是生产登录，也不发送短信或外部支付通知。

## 如何判断成功

| 状态 | 含义 |
| --- | --- |
| 待核对／待确认／待验证 | 仍在准备，尚未付款 |
| 已预约／已发布 AA | 已建立授权或请求，尚不代表付款 |
| 执行中 | 原 Operation 正在处理 |
| UNKNOWN／结果确认中 | 未确认最终结果，继续查询原操作 |
| 付款成功 | Provider 明确成功，关联 Operation 与业务状态已收敛 |
| 失败／过期／已取消 | 按关联资源和账本事实展示，不能推断其他期次结果 |

Task 完成只表示处理结束。审计链展示核对、授权、风险、原 Operation 与 Provider 证据；不展示验证码或隐藏推理。
