# 安全自评报告

## 自评范围与权限分级

本报告针对当前本地源代码、合成银行、Web渠道、后端及独立代码沙箱。版本与迁移见[文档导航](../README.md)。真实资金渠道和外部 IdP 完整验收不在本地测试证明范围。按作者要求，本地使用只保存在后端环境的身份验证码，前端仅接受用户输入；它只验证模拟流程，不能当作真实第二因素。真实TOTP能力保留为可选后端模式，生产继续禁止Mock。

当前覆盖转账、账单分析、模拟理财和订阅管理四个核心场景。默认运行方式尚未完成真实多因子链路验收，因此不能仅凭本地验证门禁宣称已满足原题的多因子要求。

| 等级 | 操作与授权 | 服务端约束 |
| --- | --- | --- |
| 绿色 | 本人账户、余额、账单、消费与理财只读资料自动查询 | 服务端 Principal、资源归属、caller 和工具白名单 |
| 黄色 | 单笔严格小于个人免密额度且日累计风险暴露≤1000元的即时转账，确认后执行 | 个人额度0—200元（默认200）；成功累计+执行中敞口+本次金额；提交重读设置并重评、摘要绑定、有效期与幂等 |
| 黄色 | 订阅读取与取消 | 读取明确授权5分钟、仅本人；取消单独确认合同和版本，不继承读取授权 |
| 红色 | 单笔达到个人额度或超过日累计阈值的转账、修改免密额度、预约／周期授权、理财申赎、恢复续费授权 | 强验证门禁已实现；当前本地校验后端身份码，可选真实TOTP。默认模式尚不等于原题的多因子认证，生产禁止Mock |

用户、模型或资料文本不能指定执行身份、风险等级或生成有效金融授权。条件 TRUE、计划完成、订单受理、预约创建和AA发布都不能替代付款确认或最终交易结果。

收款人新增、修改和删除属于资料维护，本项目不要求强验证；保留页面核对／确认、本人归属和安全写锁控制。保存或变更收款人不授权转账，实际付款仍按上表独立确认与验证。操作审计是在后台记录过程，与是否要求验证码是两项独立控制。

| 中断与接管 | 有界DAG、暂停／继续、只读步骤回退，不撤销已提交交易 | test_plans.py、test_plan_conditions.py、对应PostgreSQL套件 |

## 已知风险与残余限制

| 编号 | 已知风险 | 当前处置／验收边界 |
| --- | --- | --- |
| R01 | 真实银行与支付渠道未接入 | 全部金融业务标注模拟，不能作为生产金融接入证明 |
| R02 | development 使用合成主身份，Mock码仍用于明确标注的演示 | 生产要求OIDC及TOTP；使用真实IdP后仍需联调，不能把本地TOTP测试当成完整生产双因素验收 |
| R03 | TOTP可能被钓鱼；时间不同步影响验证 | 仅接受相邻时间步、防重放、失败锁定；尚非抗钓鱼硬件凭据 |
| R04 | Fernet服务密钥丢失或泄露影响认证器密钥 | 私密配置、加密落库、禁止日志输出、独立备份；未接HSM／外部密钥托管 |
| R05 | 理财自由语言的有限校验仍可能遗漏语义问题 | 结构化事实引用、修复与降级、禁止收益承诺；仍需对真实模型进行人工抽查 |
| R06 | 容器共享宿主内核，镜像或Docker本身可能有漏洞 | 独立低权限无网络任务，不挂载宿主／Docker socket；不宣称虚拟机级或已完成渗透测试 |
| R07 | 审计应用层只追加不等于数据库不可篡改 | 限定查询归属、保留业务证据，生产仍需独立审计存储、备份及权限隔离 |
| R08 | SSE进程内广播，多进程无统一回放 | 持久资源API恢复事实；尚无跨进程broker和完整生产监控 |
| R09 | 外部模型、用户设备与数据隐私 | 评估只用合成数据、禁止验证码／密钥进入Prompt；实际接入仍须评估数据范围和提供商策略 |

可选改进：收款人资料目前保留当前状态、创建时间和删除标记，未保存每次变更的独立历史日志。可补充变更前后摘要便于排查；该改进不要求增加强验证，赛题也未明确将收款人资料维护列为红色操作或要求单独的决策链。

## 自评方法与结论

以[测试说明](../development/testing.md)命令执行离线、PostgreSQL与Docker沙箱回归；对[验收清单](acceptance.md)进行页面验证。默认离线通过不代表已运行PostgreSQL或Docker隔离测试，实测结果应由运行日志证明。

当前提供四个模拟核心业务场景及对应安全控制。源码测试和本地隔离环境可以证明具体边界与拒绝行为，不能据此宣称真实金融业务上线许可、全部Prompt攻击免疫或任意模型输出完全正确。
