# v0.11.3 个人银行真实模型验收

日期：2026-10-15。用户明确授权后，仅向已配置的 `https://api.deepseek.com`、`deepseek-v4-flash` 发送隔离合成测试数据。没有读取现有业务数据库、用户旧对话或真实金融资料。

## 转账汇总后续验收

针对“只有流水、没有分析”的反馈，新增全部匹配记录的Decimal统计、按收款人/付款方归集、占比、最近一笔与解读，并沿用消费分析的Markdown表格样式。

全新合成数据下9条用例、19次请求通过；另以新库补测“分析最近30天转账，按收款人汇总”，2次模型请求、1次账单工具查询通过。本次共10条、21次实际模型请求，无工具失败及金融操作、工作流或计划。

黄金数据：转出6笔，每笔10元，合计60元；李小雨5笔50元，占83.3%，王海1笔10元，占16.7%；另有转入1笔10元。只展示2条明细和续页时，总额、分组和最近一笔仍相同。空结果和明确日期保留原有行为。后台完整1180项、前端118项通过。

原始合成记录：`/tmp/statement-real-v0113-analysis-results.json`、`/tmp/statement-real-v0113-single-analysis-results.json`。当前banking-assistance资源版本0.12.7；下方保留上一轮方向修复的验收记录。

## 环境与约束

新建 SQLite 数据库，加载仓库合成账户与账单，并生成4笔成功转账、1笔待处理转账、1笔失败转账及1笔成功订阅扣费。接口依赖、工具、TaskRunner和银行提供方均使用同一隔离会话工厂；不启动业务 Worker。一个“缺少历史查询工具”的旧回复样本也是专门生成的测试文本。

通过公共对话接口创建消息，再由实际 TaskRunner、LangGraph、标准 banking-assistance Skill、真实模型和 ToolExecutor 完成。HTTP请求钩子限定外部目标为 `https://api.deepseek.com/chat/completions`，全部为POST；密钥未写入记录。每条用例核对路由、工具调用、实际参数、入账事实及副作用。

## 结果

修复后8条用例全部通过，共17次真实模型HTTP请求，无工具调用失败：

| 用例 | 结果 |
| --- | --- |
| 最近有哪些转账，每页2条 | 使用账单工具，匹配4笔成功转账；未受生成的旧拒绝样本影响 |
| 下一页 | 使用相同筛选、as_of与offset=2；两页交易不重复 |
| 最近30天转给李小雨 | TRANSFER、DEBIT及姓名组合筛选，返回1笔 |
| 最近30天转入记录 | TRANSFER、CREDIT，返回1笔 |
| 2026年8月工资卡购物明细 | 先查账户，再按acc_salary、SHOPPING及月份过滤；返回0笔，与该账户种子账单一致 |
| 最近30天订阅实际扣费 | 返回3笔，包含新生成的成功扣费；不是未来提醒 |
| 2010年转账记录 | 返回空结果，无错误及虚构交易 |
| 2026年10月15日转账记录 | 北京时间当天零点至次日零点，返回4笔；未改成整月 |

所有任务均完成于ACCOUNT_QUERY，只调用get_account_statement及必要的list_accounts；没有创建Operation、Workflow或Plan，待处理转账没有被推进。

## 发现与修复

首次验收在“转给李小雨”处发现模型只传姓名、遗漏DEBIT。此次数据恰好只有符合方向的结果，但姓名筛选不能替代收支方向，因此保留失败记录并修复。

- banking-assistance资源更新到0.12.6，明确“转给某人／给某人汇款”和“收到／别人转给我”的方向。
- Manual与LangGraph执行账单工具前，共用确定性方向约束，补齐或纠正模型遗漏的明确方向。
- 下一页的筛选、截止时刻、页大小和偏移在执行层复用原始查询；模型即使重置条件也不会查询错页。未知参数仍交由严格schema拒绝。
- 新增双运行时回归，故意让测试模型省略或传错方向、重置分页条件，验证最终执行参数与结果。

初次失败及最终成功的原始记录保存在本机临时目录：`/tmp/statement-real-v0113-results.json`、`/tmp/statement-real-v0113-attempt2-results.json`。它们仅包含合成验收的工具元数据，不能作为真实银行流水使用。应用、API与网页版本仍为0.11.3；完整回归和部署证据见[本轮更新说明](../releases/release-notes-v0.11.3.md)。
