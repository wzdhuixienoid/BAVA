# v0.10.2 更新说明

更新日期：2026-10-09。数据库迁移目标：`0030`。

## 当前行为

- 即时转账支持最多 100 个 Unicode 字符的备注。修改备注会使旧确认和强验证失效；Operation、Provider 和回执保存提交时的内容。
- 单次预约与有限次按月周期转账在创建时完成核对、确认、强验证和显式预约授权。到时自动执行 Mock 转账，不冻结余额；每期重新校验余额、账户、风控与 Security Guard。周期必须明确时间和次数，不提供无限期授权。
- 自然语言时间由受限 LLM 提取语义，后端按请求接收时刻和业务时区计算并校验。缺少或歧义信息需要补充，最终时间由用户核对；页面统一显示 `YYYY-MM-DD HH:mm:ss`。
- 姓名或别名的部分匹配只提供候选，仍需用户确认；模型不能决定内部收款账户。
- AA 支持平均及手动分摊，按整数分计算。自己参与的份额记为自己承担，不向自己转账。发布请求不扣款，其他参与者以自己的身份独立确认、强验证和付款。已收金额仅统计 Provider 明确成功的付款。
- AA 核对时错误字段显示红框和逐项原因，修正后重新校验；参与者栏只填其他人，自己的份额由是否参与选项控制。
- 预约列表以任务内容为首行、执行时间为第二行；相同周期按真实 series_id 合并，逐期展开。已预约明确显示等待执行时间，无需再次提交。
- 已取消且没有 Operation 的预约可从列表删除；周期任务必须整组满足条件，采用软删除，保留审计与业务证据。
- 删除对话后已授权预约继续运行并在预约列表管理。未授权或资金处理中仍保留活动流程保护。
- 收款人支持完整账号输入及编辑、删除，后续仅显示尾号。手机号转账已移除。

## 安全和 Mock 边界

沿用 TaskRunner → 意图提取 → 确定性 Workflow → 授权 → Operation → Provider。金额使用 Decimal，API 使用十进制字符串，仅支持 CNY。身份、资源归属、expected_version、确认哈希、强验证、Security Guard、幂等、审计和 Outbox 继续生效。

即时 Approval 600 秒、强验证 300 秒不延长。预约使用固定内容、固定日期与执行窗口的一次性 Mock 授权，不能用于即时转账或 AA。只有 Provider 成功才显示付款成功；UNKNOWN 恢复原 Operation，不创建第二笔扣款。无真实银行、短信、外部支付或自动催收。

## 升级

保留数据，备份后执行 `alembic upgrade head` 并同步 API/Web。容器启动执行迁移。`0028` 移除手机号路由，`0029` 添加有限次周期授权，`0030` 添加预约列表删除标记。预约需要 `MOCK_SCHEDULED_TRANSFERS_ENABLED=true`，其余配置见 [README](../../README.md#升级到-v0102)。

## 实际验证范围

上一轮预约与对话管理修改执行相关后端 42 项（含独立 PostgreSQL Worker 竞争）、前端 61 项、类型检查与 API/Web 构建，均通过。真实网页验收了已授权预约等待执行、取消任务删除弹窗及 AA 分摊校验。测试未实际删除用户任务、撤销预约或代用户授权付款。

更早的全量后端测试和模型验收记录仍属于各自执行时刻的证据，不当作本次版本标记更新重新运行的结果。详细记录见 [转账扩展验证记录](../archive/reviews/v0.10.2/transfer-validation.md)。
