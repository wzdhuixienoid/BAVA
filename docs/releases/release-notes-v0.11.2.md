# v0.11.2：PersonalBankingAgent 整合与工具审计

当前交付日期：2026-10-15，应用版本保持 **0.11.2**，网页、API 和当前文档一致。基础银行查询与消费分析统一为 PersonalBankingAgent；现有交易授权、条件计划、订阅和理财保持独立边界。无新增迁移，无演示数据重置。

- 一个 agent:personal-banking 身份，ACCOUNT / SPENDING / COMBINED 三种配置分别加载基础查询、消费分析或两个 Skill。报告按需加载 report-source.md，完整异常工具仍只在本轮明确要求时开放。
- 普通“查询余额再分析消费”由同一 Agent 完成，不再创建 Plan。计划保留账户查询、消费分析两种能力，由相应配置执行，条件与资金操作仍通过原机制。
- 账户余额、消费快照、报告和异常结果可以同时保留；余额不进入消费指标，消费分析内部的账户定位不作为额外账户查询结果展示。
- 删除旧两个 Agent 定义，更新调用方、工具 caller、路由、脚本和测试。历史执行器仅作显式兼容映射；新任务固定配置用于恢复，缺失/无效配置拒绝执行，不重路由扩权。
- 更新 banking-assistance / financial-analysis 的指令和预算规则，两个包的独立资源版本为 0.12.4，其他包仍为 0.12.3。

## 用户行为变化

- 推荐先解释已知条件、候选优势、费用/流动性代价、不适用情形与资料缺失，再展示紧凑对比。未知预算、账户和期限不会被说成已满足。
- HTTP 与 Agent 共用 WealthAdvisoryService；原 compare 列表接口保留，新 POST /api/v1/wealth/analysis 返回 typed 分析。当前本人测评用于权限；指定高风险产品可客观比较，不变成购买推荐。
- 同预算费用调用原 purchase/redeem Decimal 规则，明确净值不变假设；时间计算新申购、获得份额、最早赎回、成交到现金到账的完整链路。历史数据统一窗口，只读已发布 NAV。
- 通用教育知识与模拟条款分开引用。没有披露资产配置/债券股票比例/信用质量时明确未知。文档 URL 分内部资料和白名单官方来源，不展示工具 ID 或接口路径。
- Task.output 保存唯一最终分析、顺序、需求、测评与产品/资料版本和时间。本人本对话快照支持重启、超过十条消息后的指代；“上次为什么”和“现在是否适合”分别使用历史和当前事实。产品名称中的“均衡/进取”不会被误当成用户的新偏好。
- 模型通过现有 LangGraph 组织批准分析块；数字、证据、候选顺序、权限和状态不可由模型改写。不验证任意金融自由文本；契约只接收完整合法块列表，最多一次修复，失败保留具体差异的确定性解释。
- 旧消息和条款不重写。旧结果缺理由时明确说明，只有用户点击才新建只读“按当前条件重新分析”任务。原金融授权、元/份、全部赎回、UNKNOWN 占用、关闭新业务后的恢复保持回归。

## 实际对话示例

以下在隔离 SQLite、测试用户、业务时钟 2026-10-09 09:00（北京时间）实际运行；浏览器使用测试组织模型与确定性解释，并非真实模型现场自由生成。

1. “我想买理财，有什么推荐？”：条件性候选，询问预算与最早用款时间。
2. “预算5000元，稳健，持有3个月”：按本次偏好列出稳健优选、稳享周周、稳享日日；账户未选不声称余额足够，三个月不冒充具体用款日。
3. “为什么第一款？”：仍解析上次第一款稳健优选；相比周周申请窗口更多，但同额净值不变情景申赎费用多5.00元（10.00与5.00元）。重启 API 后追问仍正确。
4. “为什么不选第二款？”：说明第二款也入候选，费用较低但周开放窗口更少，未捏造全面劣势。
5. “下周可能用钱，还适合吗？”：下周保留为10月12日至18日范围，按最早可能用款日筛选；最早新申购现金到账10月14日，返回无适配并追问具体日期。
6. 指定比较均衡优选/均衡周享，再问5000元费用：分别14.99/19.98元（净值不变估算），差4.99元；同一短期用款条件下明确不适合。每日开放问题解释申请不等于现金已到账。
7. “必须保本，不能亏本金”：C5 也无匹配；“风险低是否保证不亏”检索并显示低风险非保本知识。
